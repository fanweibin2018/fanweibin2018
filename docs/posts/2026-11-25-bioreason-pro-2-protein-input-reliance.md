# BioReason-Pro 2：多模态模型如何证明自己真的读了蛋白质

11 月 24 日，Goodfire、NVIDIA 与 Arc Institute 发布了 BioReason-Pro 2。它接收蛋白质序列和结构表征、功能术语预测、物种与相互作用伙伴等信息，再生成蛋白质功能解释与可供实验检验的假设。

这次更新最值得关注的地方不是又多了一个生物大模型，而是团队承认并处理了一个更基础的问题：**一个多模态模型即使答案看起来正确，也可能绕过最重要的那种输入。**

上一代 BioReason-Pro 同时拿到蛋白质表征和文字注释，但独立审计与后续内部分析都发现，它可能主要依赖容易阅读的文字线索。新版本因此删掉训练阶段的 InterPro 注释捷径，让推理更细地落到结构域、序列特征与单个氨基酸上，再调整蛋白质嵌入的数值尺度。官方实验显示，这些改变让答案对蛋白质输入明显更敏感，也改善了特征位置的描述。

这比单纯提高排行榜分数更有普遍意义。图文模型、语音语言模型、检索增强系统和带工具的 Agent 都面临同一问题：系统声称融合了多种证据，不代表每种证据真的参与了判断。

## 一个“看过答案提示”的生物模型

BioReason-Pro 2 的输入大致分成两路。

第一路是蛋白质本身。冻结的 ESM3 把氨基酸序列以及可选的三维结构转换为逐残基的数值向量，再由适配器送进语言模型。第二路是文字上下文，包括物种、已知相互作用伙伴，以及 GO-GPT 对 Gene Ontology（GO）术语的预测；运行时还可以选择加入 InterProScan 找到的蛋白质家族、结构域和位点。

最终，Qwen3.5-9B 解码器同时读取这些信息，描述分子功能、参与的生物过程、细胞位置和可能的相互作用。

可以把它想成让学生判断一台机器的用途。学生一边拿到机器内部的 X 光图——蛋白质序列与结构表征，一边拿到别人写好的标签——GO-GPT 和 InterPro 的文字。若考试答案主要能从标签抄到，学生即使得高分，也不能证明他学会了看 X 光图。

InterPro 本身并没有问题。它是成熟且有价值的蛋白质分类资源，部署时把它作为上下文也很合理。问题在于研究者若想证明模型能从原始蛋白质表征中发现新线索，就不能让训练答案被同一序列导出的文字注释完全覆盖。

## 第三方审计怎样发现“会答题但没看输入”

Harvard Medical School 团队此前审计了包括 BioReason-Pro 在内的生物推理模型。他们没有只看最终准确率，而是交换、打乱或移除不同输入，再观察模型到底跟随哪一路证据。

审计给出了一类很直观的冲突测试：ESM3 蛋白质表征来自样本 A，GO-GPT 与 InterPro 文字来自样本 B。BioReason-Pro 在 99.7% 的冲突样本中给出与文字来源一致的回答。也就是说，模型能接收到蛋白质信息，不等于该信息决定了答案。

这类测试比“注意力图看起来很亮”更有说服力，因为它提出了反事实问题：

- 保持文字上下文不变，删掉蛋白质嵌入，答案会怎样？
- 把嵌入换成长度相近的另一条蛋白质，结论会跟着改变吗？
- 打乱序列再重新计算嵌入，模型是否仍给出近似答案？
- 两路输入冲突时，最终判断追随哪一路？

如果关键输入被替换后结果几乎不动，模型声称“融合”这种输入就值得怀疑。相反，结果发生变化也只证明输入产生了影响，不能自动证明新答案正确。

## BioReason-Pro 2 改了三件事

团队没有把捷径问题当成评测报告里的一条注脚，而是用它反过来修改训练。

第一，**训练时移除 InterPro 注释**。模型不能再直接读取现成的结构域与位点清单，而要从 ESM3 表征中识别相关特征。部署推理仍可选择加入 InterPro，这时它是额外证据，而不是模型学习蛋白质表征时的答案提示。

第二，**把推理轨迹落到具体序列位置**。新的训练轨迹不只说“这个蛋白可能参与膜运输”，还要指出支持判断的结构域、跨膜螺旋、信号肽或具体氨基酸。官方研究页称，新版本用超过 23 万条这类细粒度轨迹训练；公开仓库进一步说明，发布的 SFT 检查点使用了 272,688 条 Kimi K3 生成的轨迹。

第三，**校正蛋白质嵌入与文字嵌入的尺度**。研究者发现，两种表示进入 Qwen3.5-9B 时数值规模不匹配。直接对每个位置使用 LayerNorm 虽然缩小了差异，却抹掉了不同氨基酸嵌入之间有用的幅度变化，模型甚至会把特征位置写到序列末端之外。

最终方案是 block RMS norm：对一条蛋白质的全部表示使用同一个缩放因子。它像把一张过曝的 X 光片整体调暗，保留片内不同区域的明暗差异，而不是把每个像素分别拉到相同亮度。

## 怎样证明改动不是“换个模型再刷分”

Goodfire 做了两组互补实验。

第一组是**重放同一段参考推理**，在每个词的位置阻断 ESM3 或 GO-GPT，比较下一个词的概率改变。旧模型中，两路输入的作用接近；新版训练后，推理开头的变化主要来自 ESM3。进一步分析显示，ESM3 更影响序列长度、氨基酸位置与身份、结构域描述；GO-GPT 更影响生物过程和细胞位置；伙伴信息更影响相互作用描述。

这个结果说明不同输入有了可区分的作用，但不能把每句话唯一归因给某一路，也不能证明每句话正确。官方研究页明确把它称为相对影响，而不是信息贡献百分比。

第二组是**重新生成答案**。研究者分别移除 ESM3、换入另一条长度相近蛋白质的嵌入，或先打乱序列再计算嵌入，同时保持其他输入不变。BioReason-Pro 2 的答案损失比旧版更大，支持“新版更依赖蛋白质表征”这一结论。

更细的序列定位指标也有所改善。团队报告，在其评测的特征类别中，训练数据改版后的模型识别出 83% 的已有注释特征，旧对照为 44%；移除 ESM3 后，新模型的特征召回下降 72%，旧模型下降 21%。完成尺度修正后，模型引用的氨基酸与所述位置一致的比例从 15.1% 升至 95.5%，特征位置落在真实位置前后 5 个氨基酸内的比例从 57.0% 升至 84.5%。

这些都是开发团队自己的评测。特征指标使用约 6000 条测试蛋白质，部分干预只使用 256 条；函数描述还包含由 Nemotron 3.5 Super VL 给出的模型裁判分数。因此它们适合证明设计改动是否沿预期方向生效，不能当成跨团队独立验证的通用准确率。

## 两个湿实验告诉了我们什么

输入敏感性仍然只是模型证据。团队还挑选两条较少研究的人类蛋白质，把部分假设带进实验室。

SMIM32 有 103 个氨基酸，唯一的半胱氨酸 Cys75 位于预测跨膜螺旋末端。BioReason-Pro 2 在 300 次采样中有 31% 提出 Cys75 可能发生 S-酰化；移除蛋白质输入后，300 次里没有一次提出该假设；把 Cys75 改成丝氨酸后也同样为零。湿实验使用的是 C75A 而非模型干预中的 C75S，结果支持 Cys75 依赖的 S-酰化。

边界同样重要：实验没有确定附着的是哪种脂肪酸、由哪种酶完成，也没有证明下游生物效应。模型关于信号肽的一部分解释还被生物学审查标为不合理。

另一个案例中，模型提出肾癌相关蛋白 RCDG1 与 RAB5A 有关联。共同免疫沉淀显示 Flag-RCDG1 能拉下内源 RAB5A，IgG 阴性对照没有这一信号。这支持两种蛋白存在实验关联，但不能仅凭可解释性特征确立作用机制；而且上一代 BioReason-Pro 也曾提出同一关联，不能把它完全归功于这次架构修改。

两个案例证明的是“某些可追踪假设值得拿去做实验”，不是整个模型已获得普遍的实验验证。

## 怎样试用，以及为什么多数人不该先下载权重

项目公开了推理、评测和强化学习代码。官方最短路径是准备包含 `protein_id`、`organism` 与 `sequence` 的 TSV 文件，再运行：

```bash
python scripts/data/download_assets.py --dest assets --skip-structures --skip-ia
python predict.py \
  --input data/examples/proteins.tsv \
  --output runs/example/predictions.tsv
```

这两行不是轻量演示。仓库注明推理需要一张 80GB CUDA 显卡；第一次运行还会下载 BioReason-Pro 2、ESM3、GO-GPT 及其 ESM2 编码器。输入序列只读取前 2000 个氨基酸。若开启 InterPro 在线查询，还需要真实邮箱，并应注意在线版本可能不同于训练时使用的 InterProScan 5.78-109.0。

因此，对大多数工程团队，更值得先复现的是**输入依赖评测方法**，而不是直接部署这个模型。下面的 Python 例子使用四条完全虚构的分数，演示成对消融怎样计算平均下降；它不调用 BioReason-Pro 2，也不代表任何生物学结果。

```python
pairs = [
    {"id": "P001", "intact": 0.82, "ablated": 0.31},
    {"id": "P002", "intact": 0.74, "ablated": 0.29},
    {"id": "P003", "intact": 0.68, "ablated": 0.34},
    {"id": "P004", "intact": 0.71, "ablated": 0.27},
]

intact = sum(x["intact"] for x in pairs) / len(pairs)
ablated = sum(x["ablated"] for x in pairs) / len(pairs)
drop = intact - ablated

print(f"完整输入均值: {intact:.4f}")
print(f"消融输入均值: {ablated:.4f}")
print(f"绝对下降: {drop:.4f}")
print(f"相对下降: {drop / intact:.1%}")
```

我用 Python 3 实际运行得到：

```text
完整输入均值: 0.7375
消融输入均值: 0.3025
绝对下降: 0.4350
相对下降: 59.0%
```

真实实验至少要固定样本、提示、解码参数与评分方法，只替换一种输入；对随机生成重复采样，并同时报告绝对分数和变化量。还应加入三种不同难度的反事实：删除输入、换成匹配长度的其他输入、在保持基本统计特征的情况下打乱输入。只做删除实验，模型可能因为遇到训练外的空值而退化，无法区分“真正依赖”与“格式被破坏”。

## 它适合什么，不适合什么

BioReason-Pro 2 最合适的定位是研究假设生成器与多模态模型审计样本。

它可以帮助蛋白质研究者汇总序列、结构和功能术语，提出需要人工筛选的结构域、位点或相互作用假设；也可以帮助模型开发者研究不同模态是否被使用，以及表示尺度怎样影响跨模态计算。公开的 3350 万条推理轨迹图谱还提供了大规模候选，但数量不等于真实性。

它不是已经验证的蛋白质注释数据库，更不是临床或诊断系统。Hugging Face 模型卡把发布版本定义为初始研究版本，明确要求专家审查和实验验证，不用于诊断、治疗或患者照护决策。

与普通蛋白质语言模型或分类器相比，它能生成较完整的自然语言假设，却引入了语言模型幻觉和模型裁判偏差；与纯文本大模型相比，它能直接读取序列与可选结构，但部署成本明显更高；与 InterPro 等成熟数据库相比，它可能提出注释之外的猜想，却不能替代数据库的可追溯证据。

## 仍然不能越过的边界

现在就把 BioReason-Pro 2 当成成熟科研基础设施还太早。

- 论文仍标为“即将发布”，当前主要证据来自团队研究页、仓库和模型卡，完整实验方法尚未经过论文形式的公开审阅。
- SFT 使用的 Kimi K3 推理轨迹没有发布，仓库明确说明监督微调不能由公开数据完整复现；强化学习阶段可以复现。
- 模型与 ESM3 合计规模不小，官方推理路径要求 80GB 显存，训练和基准复现还涉及约 108GB 至 150GB 的结构数据。
- 官方函数预测结果部分依赖 LLM 裁判；发布的基准生成中还修复过 444 条无结构蛋白质被批处理为全零骨架的问题，修复后报告指标变化不超过 0.002。
- 模型为固定的蛋白质功能讨论格式训练，官方承认它对其他输出格式的指令遵循较弱。
- 序列超过 2000 个氨基酸会被截断，结构缺失、版本不一致和外部注释更新也会改变输入条件。
- 两个湿实验案例很有启发，但样本太少，不能证明广泛可靠性；其中 RCDG1 还是训练集中出现过的蛋白质。

所以，这次发布真正可复用的成果，不是“AI 已经会发现蛋白质功能”，而是一套更诚实的开发顺序：先测模型到底使用了什么输入，再根据内部表示修正训练，最后把假设交给独立数据和实验验证。

多模态系统最危险的错觉，是界面上摆着许多证据，内部却只走了最省力的一条路。BioReason-Pro 2 没有彻底解决这个问题，但它展示了怎样把“模型真的看了吗”变成可干预、可度量、也可以被证伪的工程问题。
